# AGENTS.md — instructions for LLM agents (and a checklist for humans)

> Read this file FIRST, every session. It is the contract that keeps four people and several
> LLM agents from stepping on each other. `CLAUDE.md` just imports this file.

## 1. What this project is

**Waypoint**: an iPhone app (Swift/SwiftUI, iOS 17+, Pro iPhones with LiDAR) for indoor navigation
by blind users. A sighted volunteer scans a building; a blind user is later guided with spatial
audio + haptics. 24-hour hackathon, 4 people. Demo: blindfolded judge walks to a room in Rice Hall.
Full design: `Architecture.md`. Original goal: `objective.txt`.

## 2. Orient yourself in 60 seconds

1. `docs/MODULES.md` — who owns which files and what is DONE / SCAFFOLD / TODO.
2. `docs/WORKLOG.md` — newest entries at the TOP. What changed recently, what is broken.
3. `docs/DECISIONS.md` — why things are the way they are (do not re-litigate without a reason).
4. `make help` — every build/test command.

## 3. Hard rules

1. **Log every change.** Before you finish a task, add an entry at the TOP of `docs/WORKLOG.md`
   (template at the top of that file): files created/edited/deleted, commands run, what you
   verified, what you did NOT verify, open problems. Humans and other agents rely on it being
   complete. If you change status of a module, also update `docs/MODULES.md`.
2. **Stay in your lane.** Each directory has an owner (table in `docs/MODULES.md`). Edit another
   owner's files only to fix a compile error or when asked, and say so in the WORKLOG.
3. **The data contract is frozen-ish.** `Package/WaypointCore/Sources/WaypointCore/Model/*` is
   used by everyone. Do not rename/remove fields casually. If you must change it: update tests and
   `Samples/rice-hall-sample.json`, bump `BuildingMap.schemaVersion` if the JSON shape changed, and
   announce it at the top of the WORKLOG with the tag `CONTRACT CHANGE`.
4. **Where does code go?**
   - Pure logic (no Apple UI/AR/audio frameworks) → `Package/WaypointCore/Sources/WaypointCore/…`
     **with a unit test** in `Package/WaypointCore/Tests/WaypointCoreTests/`. This is what we can
     verify without a phone, so push as much logic here as possible.
   - Anything importing ARKit / AVFoundation / CoreHaptics / Vision / MultipeerConnectivity /
     SwiftUI → `Waypoint/<Area>/…`.
5. **Verify before claiming done.** Run `make test` and `make typecheck`; both must pass. Quote
   their result in your WORKLOG entry. Never write "works" for anything involving ARKit, LiDAR,
   audio, haptics or Multipeer unless a human tested it on a phone — write
   **"UNVERIFIED ON DEVICE"** instead. Agents cannot test on hardware.
6. **Never edit generated files.** `Waypoint.xcodeproj` is generated by XcodeGen (`make gen`) and
   git-ignored. Change `project.yml` instead. `Waypoint/Info.plist` is also generated from
   `project.yml` (the `info:` block) — edit it there.
7. **Do not commit secrets or personal config.** `Config/Local.xcconfig` (team id) is git-ignored.
8. **No `sudo`, no global installs without telling the human.** If a setup step needs admin
   rights (e.g. `sudo xcodebuild -runFirstLaunch`), stop and tell them.
9. **Do not add dependencies.** Apple frameworks only (decision D-003). Ask first.
10. **Build output goes outside the repo** (`~/Library/Caches/Waypoint`), see D-005. Never run
    `xcodebuild`/`swift build` with output inside the repo directory.

## 4. File conventions (so every file explains itself)

Every Swift file starts with a header comment containing: `File`, `Owner`, `Purpose`, key
design notes (coordinate frames, threading), `Status` (DONE / SCAFFOLD / TODO list with the
owner letter, e.g. `TODO(B): …`). Keep it accurate when you change the file. Use `Log.<area>`
(`os.Logger`) not `print`. Comment the WHY, not the obvious WHAT.

Coordinates (easy to get wrong): meters; ARKit convention: +x right, +y up, −z forward (camera
looks down −z). Map frame == the ARKit world frame of the scan session. Bearing: positive =
right of the user's facing. See `Geometry.swift` and its tests.

## 5. Commands (all from the repo root)

| Command | What it does | Needs phone? |
|---|---|---|
| `make test` | WaypointCore unit tests on macOS (seconds) | no |
| `make typecheck` | type-check the iOS app against the iOS SDK | no |
| `make gen` | regenerate `Waypoint.xcodeproj` from `project.yml` | no |
| `make check` | full unsigned `xcodebuild` compile (needs healthy Xcode) | no |
| `make devices` | list connected iPhones | yes |
| `DEVICE=<id> make run` | build + sign + install + launch + stream console | yes |
| `make doctor` | diagnose the machine | no |

## 6. Working simultaneously (Live Share or git)

See `docs/WORKFLOW.md`. Short version: claim files by owner area, make small focused edits,
log them, never "tidy up" files you do not own, and re-read a file before editing it because
someone else may have changed it a minute ago.

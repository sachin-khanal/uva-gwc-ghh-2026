## Confirmed failures and changes

1. The viewer accepts schema 4, but the deployed geometry validator rejects it. Current real maps are schema 3. U3's schema-4 native publication is therefore not covered by the successful existing-map browser tests. Align the deployed validator/merge implementation with reviewed U3 changes before releasing that path. No live migration was applied here.
2. `extend_building` can add a new mesh manifest when updating an existing building without calling the file-verifying publication API. The dedicated `publish_mesh_assets` tests pass, including contributor ownership, missing file and size rejection, append-only behavior, delisting permissions, exact-path reads and swapped-size denial. Those protections are insufficient if callers can take the separate map-update path. The failing reproduction creates only a transaction-local map/user and rolls back.
3. Disabled graphics exposed a viewer error: a later generic import message hid the WebGL failure and left the estimated-building state selected. Fixed `web/app.js` to clear that state and retain the error in the geometry status beside the map. Route controls remain available. The live fallback regression now passes.
4. The old richness SQL test used nullable comparisons and the older mesh-update contract. Updated it to exercise `publish_mesh_assets`, supply transaction-local storage metadata and use null-safe assertions. The bypass is tested separately and explicitly fails; it is not hidden by a successful metadata suite.

## Database evidence and boundaries

Inspected deployed migration history, RLS policies, security-definer function permissions and security advisors through the existing Supabase MCP configuration. No production migration or policy was changed. SQL fixtures and temporary grants were rolled back. Final state: four canonical buildings, 22 storage object rows, zero fixture users.

Security advisors still report the existing mutable `touch_updated_at` search path, intentional anonymous access/security-definer API warnings, and disabled leaked-password protection. `narration_usage` has RLS with no client policy intentionally (service role only). This inspection is not a claim that all advisor warnings were fixed.

The mesh SQL suite was adapted from latest `origin/U3` for managed Supabase: removed psql-only commands and unnecessary storage-table DDL, and scoped count assertions to fixture paths so existing real buildings do not invalidate them. No real object bytes were uploaded, overwritten or deleted by these SQL tests. Public-client tests create ordinary anonymous auth identities, as the viewer normally does.

Run the live harness using the instructions in `tools/README.md`. Real floor-plan screenshots are kept outside the repository under the OS temporary directory. The SQL compatibility and bypass files are **known failing deployment regressions**; run them transactionally and keep them failing until the backend is actually corrected.

## What this does not establish

No fresh phone scan/upload was performed. Existing phone-made data was checked through its live publication and local backup, which does not prove a new capture/export/upload cycle. No physical navigation, LiDAR capture fidelity, audio/haptics, Safari/WebKit, or non-software GPU validation was performed. Native device-facing behavior remains **UNVERIFIED ON DEVICE**. The tests did not apply U3's unmerged native/SQL integration or perform a hosted deployment.
